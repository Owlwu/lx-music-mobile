# 移动端媒体弹窗界面统一与回归

这轮针对 Android 歌词匹配、封面匹配和歌曲标签编辑。真机巡检发现，三个弹窗的标题、动作按钮和辅助文字层级有差异；匹配候选的选中提示较弱，候选列表占据较多预览空间，封面候选的专辑名又容易被截断。

## 实施计划

1. 为三个弹窗统一标题栏、间距、表单与搜索输入的视觉层级，以及主要、次要和危险操作。
2. 压缩匹配候选卡片，加入明确的选中标记，给歌词和封面预览留出空间。封面候选分数说明其含义，选中后完整显示专辑名。
3. 检查构建、样式和业务测试，再在 Android 上走通歌词预览滚动、封面候选和标签编辑，记录实测范围、结果及审查关注点。

## 问题与修复

| 问题 | 修复 |
| --- | --- |
| 三个弹窗标题位置和层级各异，「应用」与「保存」和「取消」区分不足。 | 三个入口共用标题栏、输入框样式、按钮和页脚。沿用原主题的按钮文字和背景色，通过字重和边框区分操作。关闭和动作按钮具备无障碍名称或文本与按钮角色。 |
| 匹配候选选中仅靠相近的浅色底区分，卡片占用预览高度。 | 歌词和封面共用紧凑候选卡片，选中时显示描边和勾选图标，并向无障碍服务提供选中状态。候选列表高度按实际可用区域限制，预览单独滚动。 |
| 封面评分容易被理解为发行版本一致，候选卡片截断专辑名。 | 将百分比标为「歌曲匹配度」，选中后在封面预览中展示可换行的完整专辑名。候选排序和评分规则沿用原实现。 |
| 标签页把文件名显示为可输入的字段。 | 标签页统一输入样式，文件名设为只读，歌曲名、艺术家和专辑继续可编辑。 |

## 验证记录

- 类型检查、涉及组件的 ESLint、5 组业务测试和 Android ARM64 Release 构建通过。
- 最终 Release 包覆盖安装到 Android 真机。用《かつて地球は白かった》验证网易云候选选中、中文翻译与罗马音显示、歌词正文上下滚动，以及选中前「应用」禁用。验证了歌词与封面候选的无障碍名称及选中状态。
- 封面匹配验证了 iTunes 候选、图片预览、完整单曲专辑名和「歌曲匹配度」。标签编辑验证了输入框聚焦、键盘弹出时保存和取消保持可见，以及取消退出。
- 真机验证在取消前结束，未执行应用、保存或删除。测试歌曲的音频和已有 LRC 文件哈希保持一致。真机功能检查使用绿色浅色主题。

## 原主题配色与圆角

根据使用反馈，恢复此前弹窗的翠绿标题栏、原按钮与候选背景、标题与辅助文字色。选中描边和勾选使用各自主题原有的强调色。

沿用原版接近直角的样式。弹窗、按钮、匹配搜索框、封面预览恢复为 4 dp 圆角，候选卡片恢复为 6 dp，标签编辑输入框沿用原组件的 2 dp。

## DS 审查关注点

- 三个弹窗的标题、操作顺序、状态样式是否一致。检查窄屏或较长译文下的换行、按钮触控范围和焦点顺序。
- 重点看候选列表与预览的滚动边界。复查网易云原词、翻译、罗马音和切换候选后预览回到顶部。
- 对照封面候选的不同专辑，确认预览信息足以选版本。检查应用或删除仍沿用原确认与写入路径。
- 本轮范围为三个媒体弹窗。大歌单快速滚动、暂停定位歌词和批量补全另见[移动端巡检问题修复与回归](移动端巡检问题修复与回归.md)。
