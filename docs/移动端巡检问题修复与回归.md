# 移动端巡检问题修复与回归

本轮接续 Android 真机巡检，处理播放定位、快速滚动、批量补全、列表搜索反馈和播放控件的无障碍名称。媒体弹窗改造另见[移动端媒体弹窗界面统一与回归](移动端媒体弹窗界面统一与回归.md)。

## 实施计划

1. 修复暂停定位后的歌词高亮，稳定大歌单快速滚动的手势和最终位置。
2. 将批量补全分成只读扫描和确认后的写入，限制自动写入的候选。
3. 补齐列表搜索状态与本地化，并为列表和播放器控件增加无障碍标签。
4. 检查回归测试和 Android Release 构建，在真机上验证各流程并记录审查边界。

## 问题与修复

| 问题 | 修复 |
| --- | --- |
| 暂停时定位，播放时间变化后歌词仍停在旧位置 | 播放器收到进度定位事件时，按新位置与歌词偏移计算当前行，立即更新应用内歌词，维持暂停状态。更换歌词或切换翻译后也按暂停位置定位。 |
| 7,116 首歌曲的列表向上长拖时，滚动条有时只移动一小段 | 改为复用原生 Slider 的竖向滚动条。手指拖动期间滑块跟随触点，松手定位列表，避免重绘列表打断手势。 |
| 批量补全确认前看不到实际缺失数，首个候选分数过低也可能被写入 | 先扫描并显示可补全歌曲、缺歌词、缺封面及无法处理的数量。确认前不查询在线候选或写入歌词和封面。自动候选至少 0.90 分，歌词还需有时间轴且排除伴奏标记，封面需与本地专辑名归一化后相同。待手动匹配单独统计。确认后重新读取目标状态，并在进程内的同名文件写入队列中再次检查已有文件。 |
| 列表搜索无结果时仍像普通列表，简体中文下显示英文占位文案 | 三种语言分别提供列表搜索占位与空结果提示。清空、退出和切换列表会让过期查询失效。 |
| 播放器控件在无障碍树中只有图标字符 | 横竖屏播放器与底部播放栏提供上一曲、播放或暂停、下一曲名称和按钮角色。歌曲更多菜单提供带歌名的标签。 |

## 核验

- 5 组业务测试、TypeScript 检查、改动组件的 ESLint 和 Android ARM64 Release 构建通过。
- 业务测试覆盖暂停定位的时间边界和偏移、批量预检取消、无时间轴或低置信候选、跨专辑封面、确认期间出现同名文件，以及写入时保护已有歌词与封面。
- Android 真机用《かつて地球は白かった》验证两次暂停定位，歌词列表随进度更新，播放按钮仍显示「播放」。Android 无障碍树显示「上一曲」「播放」「下一曲」及歌曲更多操作的名称。
- Android 真机完成 7,116 首歌的批量预检，显示 2,059 首可尝试补全，缺歌词 2,056 首、缺封面 10 首、无法处理 5 首。在确认页取消了任务。
- Android 真机用原生滚动条做了两轮长拖，覆盖约 350、650、800 毫秒的操作。顶部歌曲序号依次为 5,601、592、5,500、783、5,597。
- 验证了简体中文搜索占位、快速输入后的空结果提示、清空和取消，也确认常用关键词仍能显示匹配结果。
- 最终 Release APK 已覆盖安装并比对手机上的安装包哈希。真机批量操作停在确认页，实际写入通过测试夹具验证。测试歌曲的 FLAC 和 LRC 哈希与巡检前一致。

## 原主题配色

根据使用反馈，列表、播放页、歌词高亮和播放栏恢复巡检前的主题色与文字色。快速滚动仍由原生控件处理，滑块恢复平时的灰色和拖动时的主题强调色。

## DS 审查关注点

- 复查歌词定位事件和异步加载的先后顺序，特别是暂停、恢复进度及切换歌词来源。
- 复查批量确认、取消与同名文件写入的边界。当前置信阈值为 0.90，封面在专辑名缺失时留待手动匹配。
- 复查原生滚动条在长列表、横屏、多列和无障碍调节时的位置同步。本轮长拖实测使用 Android 竖屏。
